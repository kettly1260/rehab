# CodeGraph

This environment may provide a CodeGraph MCP server through `codegraph_*` tools.

CodeGraph is a tree-sitter-parsed knowledge graph of source-code symbols, edges, definitions, references, and files. It is intended for structural analysis of software repositories.

## Applicability

Apply the CodeGraph rules below when:

- The current task concerns a software codebase
- `codegraph_*` tools are available
- The question is about code structure, symbols, call relationships, data flow, dependencies, or change impact

Prefer CodeGraph for repositories containing substantial:

- Application code
- Libraries
- Scripts
- Tests
- Build systems
- Software configuration
- Frontend or backend source code

Do not use or initialize CodeGraph merely because a directory is a Git repository.

Do not initialize or require CodeGraph for repositories primarily containing:

- Chemistry experiment records
- Spectra and instrument data
- Literature collections
- Obsidian vaults
- Research notes
- Markdown documentation
- Raw-data archives
- Images, tables, reports, or theses
- Other primarily non-code research materials

Small helper scripts do not by themselves make a chemistry or documentation repository a CodeGraph project.

For a primarily non-code repository, use CodeGraph only when the user explicitly requests analysis of a substantial source-code component.

If `codegraph_*` tools are unavailable, silently fall back to available native search and file-reading tools. Do not repeatedly report that CodeGraph is unavailable.

## When to prefer CodeGraph over native search

Use CodeGraph for structural questions such as:

- Where is a symbol defined?
- What calls this function?
- What does this function call?
- How does one component reach another?
- What would break if a symbol changed?
- What is a symbol’s signature?
- Which files and symbols are relevant to a feature?
- How are several related components connected?

Use native search and file reading for:

- Literal strings
- Comments
- Log messages
- Error text
- Configuration values
- Markdown content
- Documentation prose
- Experimental records
- Spectra metadata
- Exact filenames
- Non-code content
- Files already known and opened

| Question                                      | Preferred tool      |
| --------------------------------------------- | ------------------- |
| Where is X defined? / Find symbol named X     | `codegraph_search`  |
| What calls function Y?                        | `codegraph_callers` |
| What does Y call?                             | `codegraph_callees` |
| How does X reach or become Y?                 | `codegraph_trace`   |
| What would break if Z changed?                | `codegraph_impact`  |
| Show Y’s signature, source, or docstring      | `codegraph_node`    |
| Give focused context for a task or area       | `codegraph_context` |
| Show several related symbols’ source together | `codegraph_explore` |
| What files exist under a path?                | `codegraph_files`   |
| Is the index healthy?                         | `codegraph_status`  |

## Rules of thumb

- Answer structural questions directly using CodeGraph rather than delegating the same exploration to a separate agent.
- For architecture or “how does X work?” questions:
  1. Start with `codegraph_context`
  2. Then use one focused `codegraph_explore` call for the surfaced symbols

  1. Start with `codegraph_trace`
  2. Then use one focused `codegraph_explore` call for the relevant bodies

  - The indexed result reports staleness
